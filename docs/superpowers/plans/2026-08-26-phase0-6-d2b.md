# Phase 0.6 D2-B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the predeclared D2-B complementary orthogonal-array diagnostic as a new child execution epoch linked immutably to the completed D1/D2-A/D3 parent evidence.

**Architecture:** Extend the existing Phase 0.6 stage machinery to understand a `d2b` stage while keeping the original parent output read-only. A child protocol lock binds the new execution SHA to the D2-B addendum and exact parent protocol/D3 hashes. D2-B analysis reuses the D2-A additive decomposition and bootstrap rules, while a separate post-D2-B adjudicator compares D2-A and D2-B before any further escalation.

**Tech Stack:** Python 3, pandas, NumPy, PyTorch, pytest, Ruff, Bash, tmux.

**Spec:** `docs/superpowers/specs/2026-08-26-phase0-6-d2b-execution-addendum.md`

## Global Constraints

- Parent Phase 0.6 execution SHA is `1718402df1d6ef344168677e6d26ea664708e1bc` and its D1/D2-A/D3 output remains immutable.
- D2-B uses only cohort `401..405`, subset `501..505`, model `601..605`.
- Reserved confirmatory seed ranges remain forbidden.
- D2-B mapping is exactly `k=(i+2j) mod 5`.
- D2-B executes exactly 100 fresh child cells: 25 triples x N `{5,40}` x flow `{none,time_scaled}`.
- Bootstrap is exactly 10,000 resamples with seed `20260826`.
- No D4 or full-factorial execution command may be added.
- Parent evidence is read-only; child output has its own protocol lock and execution SHA.
