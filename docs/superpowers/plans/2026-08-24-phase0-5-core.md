# Phase-0.5 Core Mechanistic Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the approved Phase-0.5 synthetic protocol as an isolated, resumable research pipeline that selects flow/jump/uncertainty mechanisms on five development seed bundles, freezes one architecture, then evaluates it against capacity-matched controls on ten unseen confirmatory bundles without changing historical Phase-0 outputs.

**Architecture:** Keep the frozen Phase-0 modules and scheduler intact for historical reproducibility. Add a separate `afmc_fm.phase05` package that builds strict pre-event representations, exposes explicit flow/jump/uncertainty variants, runs sequential Stage-I mechanism selection, serializes an immutable Stage-II candidate, executes Stage-III/IV shards with spawn-based CUDA-aware workers, and derives the preregistered nAULC/statistical/robustness artifacts. Reuse stable generic helpers such as simulator worlds, patient splitting, device resolution, metrics, Torch ridge, and atomic-write patterns, but give Phase-0.5 its own protocol identity and persistence schema.

**Tech Stack:** Python 3.11+, PyTorch, NumPy, pandas, SciPy, scikit-learn, matplotlib, PyYAML, `concurrent.futures.ProcessPoolExecutor`, pytest, Ruff.

**Spec:** `docs/superpowers/specs/2026-08-24-phase0-5-mechanistic-redesign-design.md`

## Global Constraints

- Historical Phase-0 behaviour at anchor `be5a66b2e45362f60c90844e4e25673fb7bb3e21` must remain reproducible; do not change the semantics of `FlowJumpAdapter`, `build_patient_sequence`, or the existing Phase-0 scheduler.
- Official Phase-0 execution commit `d6f105eee73fcb8e9cc5987d292b1bb98a687382` remains the baseline scientific record.
- Phase-0.5 uses strict pre-event history `H_<t`; current-event information must not enter the Phase-0.5 representation.
- Assimilation semantics stay fixed during Stage I: representation + `values * masks` + masks into a GRUCell.
- Residual jumps are eligible only for simulator events with `EventType.INTERVENTION` and code `SYNTHETIC_INTERVENTION`.
- Fixed time scale for the new time-scaled flow is `tau_days = 30.0`; this value is frozen before Stage-I results.
- Development bundles are exactly `(401,501,601)` through `(405,505,605)` for `(cohort, subset, model)` seeds.
- Confirmatory bundles are exactly `(701,801,901)` through `(710,810,910)`.
- The two seed sets are disjoint from each other and from the Phase-0 seeds.
- Train sizes remain `{5,10,20,40,80,100}`; primary low-N nAULC uses only `{5,10,20,40}`.
- Stage-I selection is sequential, not a Cartesian architecture search.
- Stage III may not start without a persisted immutable `frozen_candidate.json`.
- Once `confirmation/STARTED` exists, code must refuse any mutation of `protocol_lock.json`, Stage-I selection artifacts, or `frozen_candidate.json`.
- Stage-IV robustness cannot change the Stage-III result or rescue a Stage-III failure.
- The optional observation-intensity diagnostic is intentionally split into the companion plan `docs/superpowers/plans/2026-08-24-phase0-5-observation-diagnostic.md`; do not add propensity correction to this core plan.
- Do not launch official Stage-I, Stage-III, or Stage-IV experiments as part of implementation. Implementation ends after unit/integration tests and compact smoke validation pass.

- [ ] **Step 5: Implement the model**

Use `state_dim=24`. The time-scaled flow is exactly:

```python
delta = delta_t.clamp_min(0.0) / (self.time_scale_days + delta_t.clamp_min(0.0))
candidate = torch.tanh(self.time_flow(state))
return state + delta.unsqueeze(-1) * candidate
```

Residual jump is:

```python
features = torch.cat([state, event_features], dim=-1)
gate = torch.sigmoid(self.jump_gate(features))
delta = torch.tanh(self.jump_candidate(features))
return state + jump_eligible.unsqueeze(-1) * gate * delta
```

Keep zero initial state and the historical `torch.where(update_mask, updated_state, pre_state)` rule. An opportunity-only step therefore remains pre-state exactly.
